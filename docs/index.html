No. 01 · the fleet

Thirty agents.
One screen.

Aurium is an orchestration daemon for coding agents. Each one runs in its own container, on its own git worktree, on its own branch, so their trees never touch. The window shows the whole fleet at once: what every agent is doing, what it costs, and which ones are sitting idle waiting on you.

No. 03 · open source

Yours to read,
fork and run.

MIT licensed, every line of it. A Go daemon, a frontend with no bundler, a thirty line Tauri shell. make build needs only Go. The API in api/openapi.yaml is the product boundary, so anything the window does, you can do too.

One agent is a chat window. Thirty is an operations problem.

Running agents in parallel is the easy half. Knowing what they are all doing is the half nobody built. Aurium is a daemon that owns the fleet, containers and branches and context and credentials and spend, plus a window that makes the fleet legible at a glance.

No. 04 · the part nothing else does

A blocked agent is an idle agent. Aurium comes and finds you.

When an agent reaches for a capability it does not hold, a network call or a write outside its worktree or a secret, the daemon holds the call and asks. Approving executes the held call inside the daemon and hands the agent the result, so it resumes where it stopped instead of starting over. The desktop app raises a native notification, because a window behind three others is a window you are not reading.
